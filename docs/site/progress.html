01

Execution engine

Confirmed by reading clorus-codegen and the LLVM linkage in clorus-cli: this is not an interpreter or a bytecode VM. It's a real LLVM 18 compiler with two genuine, independent front doors — and both stay, per direction: Coral (the GUI toolkit at ~/Workspace/github/coral) is a live downstream consumer of both.

⚙ AOT — clorus build

commands.rs:876–897, pack.rs:65

Emits real object code via TargetMachine::write_to_file(..., FileType::Object, ...), then shells to cc to link against libclorus_runtime.a plus any FFI static libs. Produces a genuine native executable.

⚡ JIT — clorus run (default)

commands.rs:1347, 1912

create_jit_execution_engine at OptimizationLevel::None, with a legacy compile-link-run path as fallback. This is the path used for the language-level test sweep below.

Constraint, not a decision to revisit

Both modes share one codegen path (CodeGen<'ctx> walking the AST straight to LLVM IR — no separate bytecode layer), so keeping both costs nothing architecturally. Any roadmap item below that touches codegen must ship for both AOT and JIT, verified against Coral's actual usage before merging.

02

Rust interop — the actual differentiator

Real and working end-to-end, not stubbed — but narrower than "seamless" implies today. The mechanism is a source-scraping analyzer (clorus-ffi-gen, built on syn), not an attribute-macro system.

03

Correctness bugs — the "no surprises" list

Everything here was reproduced directly, not read off a doc. These are the items that most directly contradict "Clojure semantics, uncompromised."

Critical · semantics

Maps and sets are mutated in place, not persistent

clorus-runtime/src/map.rs:167 — clorus_map_assoc literally mutates the existing map ((*map_ptr).assoc(...)), self-documented as "TODO: Phase C, create a new persistent map." set.rs has the identical pattern. (assoc m :a 1) is visible through every other reference holding m — this is the single highest-priority fix; vectors and lists are genuinely persistent (32-way trie, structural sharing), so maps/sets are the outlier, not the norm.

Critical · crash · Apple Silicon

FFI calls inside a let binding corrupt pointers on arm64

repros/codegen-bug-minimal-repro.clrs — reproduced against coral-gfx: an FFI-held pointer (e.g. a window handle) survives an FFI call made outside a let, but SIGBUS/pointer-auth-faults when the same call sequence happens inside a let binding, even with pure-Clorus code between the calls. Root cause not yet isolated (candidates: FFI calling-convention transition, let-binding codegen, or register allocation around the FFI boundary). This is the one bug on this page with a direct, first-party downstream victim: Coral is exactly the FFI-heavy, arm64 caller this would hit.

Critical · crash

5 still-failing tests in the checked-in suite

tests/language/test-numeric.clr panics inside JIT-compiled _clorus_sub ("panic in a function that cannot unwind"). test-core-long-tail-3, test-core-sort-behavior, test-core-sort-error-paths abort silently (SIGABRT, exit 134, no output). test-core-long-tail-1 cascades an unhandled type error ("Cannot add Nil and Long", ~40 times) rather than crashing. None of these are edge-case fuzzing finds — they're in the existing suite, run by tests/run_all_tests.sh, and unaffected by the STM/vector/agent fixes below.

Fixed since 2026-07-30

STM, vector, and hardcoded-arity bugs found and resolved

dosync now actually retries the transaction body on commit conflict instead of silently continuing with a stale result (the prior TODO literally said "just continue after abort"). commute now has real deferred, replay-at-commit semantics instead of being an alias for alter. PersistentVector no longer corrupts nth past 1,024 elements (a raw leaf was being written where a subtree belonged). alter/send/agent dispatch no longer hardcode "named top-level function, ≤2 extra args" — closures, vars, and any arity now work. alts!! no longer busy-polls every 100μs. All verified with new passing unit tests and a clean 475/0 cargo test --workspace run.

Correctness · hardcoded

merge silently requires args wrapped in a vector

clorus-codegen/src/codegen/calls.rs:16–18,203 — arity is hardcoded to exactly 1 argument, dispatching to a runtime function expecting a vector-of-maps. Idiomatic (merge m1 m2) errors; the only passing test writes (merge [m1 m2]). keys/vals are separately defined twice (native + shadowed stdlib) — dead code, not a bug, but exactly the kind of surprise that erodes trust in the builtin set.

Reliability

recur outside an explicit loop has no guaranteed TCO

codegen/mod.rs:4200–4210 — self-recursive recur at the tail of a plain fn re-emits a normal call and leans on LLVM's own tail-call optimization rather than an explicit musttail/trampoline. It'll usually work at -O, and silently blow the stack when it doesn't — which is the definition of a surprise for a language whose whole pitch is Clojure-shaped recursion.

Three copies of core, one compiler bug

stdlib/_variants/ holds three dead, unreferenced snapshots of core (0 references anywhere in crates/). stdlib/transducers.clr.disabled is a fuller, better implementation than the active one — disabled because multi-arity functions returning closures fail to compile when the file is loaded as stdlib (works fine in user code). That's a real, fixable codegen scoping bug, not a design gap, and unblocking it recovers remove/drop/take-while/cat/mapcat/sequence/partition-by for free.

Roadmap to production

Ordered by what would most embarrass the "Clojure semantics, uncompromised" pitch if a real user hit it first. Every phase below preserves AOT + JIT and Coral's existing FFI contract — nothing here is a green-field rewrite.

Phase 0 — Stop the bleeding

done, 2026-08-01

Make "it builds, it tests, the docs are true" actually true, before building on top of it.

  • done Fixed the test_support breakage at the root cause — main.rs was double-compiling the CLI as a second crate root; now depends on the lib crate directly.
  • done Removed tracked build binaries; deleted tests/features/, tests/_archived/, stdlib/_variants/.
  • done tests/run_all_tests.sh no longer aborts on the first failure — verified with a real full-sweep run.
  • done Committed docs/generated/ and docs/gui/; mkdocs nav resolves 10/10.
  • done Archived the 7-file root audit-doc cluster.

Phase 1 — Correctness: no hardcoded surprises

in progress

Fix the things that violate Clojure semantics or crash on existing tests, before adding anything new.

  • done dosync now retries on conflict instead of silently continuing; commute now has real deferred semantics instead of aliasing alter; the vector-overflow corruption past 1,024 elements is fixed; alter/send/agent dispatch no longer hardcode arity/lookup-by-name.
  • next up The Apple-Silicon FFI-inside-let pointer corruption (repros/codegen-bug-minimal-repro.clrs) — highest priority given it's the one bug here with a live first-party victim (Coral).
  • Replace mutate-in-place maps/sets with a real persistent HAMT (mirrors the existing vector trie's structural-sharing pattern) — still the single highest-leverage semantics fix remaining.
  • Root-cause and fix the 5 remaining failing tests (test-numeric.clr and 4 stdlib long-tail/sort tests) — each becomes a permanent regression test in Phase 3.
  • Fix merge's hardcoded 1-argument arity to accept idiomatic (merge m1 m2 ...); delete the dead shadowed keys/vals stdlib defs.
  • Give recur self-tail-calls guaranteed TCO (explicit trampoline or LLVM musttail) instead of hoping the optimizer cooperates.
  • Integrate lazy-seq with core seq/first/rest/map/filter instead of a parallel lazy- API.

Phase 2 — Stdlib completion

4–8 weeks, parallel with Phase 3

Close the ~50%→~85% gap on the symbols real Clojure code reaches for constantly.

  • Fix the stdlib-only multi-arity-closure compiler bug, re-enable the fuller transducers.clr.disabled implementation.
  • Highest-frequency gaps first: a real clojure.string namespace, for, some/peek/pop/find, condp/as->/cond->, defn-/in-ns/import, future/promise/pmap, hash/identical?/not=, bit ops, format/pr/prn, memoize/fnil.
  • Extend scripts/docs/build_status.py to compute stdlib coverage against a real symbol list, so the coverage numbers in this report regenerate instead of going stale like their predecessors did.

Phase 3 — Test coverage for the whole language

3–5 weeks, parallel with Phase 2

This is the direct answer to "hope it covers the complete language" — right now it doesn't, and the runner was hiding that fact.

  • One canonical test tree (Phase 0 already kills the tests/features/ duplicate) with a systematic matrix: every special form, every core macro, every stdlib function gets at least one positive case and one edge/error-path case.
  • Every Phase 1 crash fix ships with the crash as a permanent regression test.
  • Grow tests/parity/ from 11 cases into a real differential corpus against a JVM Clojure install, so semantic drift (like the map-mutation bug) gets caught automatically instead of by manual audit.
  • Stand up CI (none exists today) gating on: Rust unit tests, the full .clr sweep, and the parity corpus — for both AOT and JIT paths.

Phase 4 — Rust interop hardening

4–6 weeks

Make the actual differentiator live up to "seamless" — and confirm what Coral needs from it today, since it's the one real production consumer.

  • Audit Coral's actual FFI usage first — it's the only ground truth for what "seamless" needs to mean in practice.
  • Expand the type whitelist: Vec<T>, Option<T>, Result<T,E>, and a path for structs/enums (even if via opaque handles initially).
  • Support impl-block / associated-method APIs, not just top-level pub fn — most real Rust crates are exactly the shape currently rejected.
  • Investigate a Rust→Clorus embedding API if Coral needs one; document the supported FFI surface precisely so "should work" stops being the answer.

Phase 5 — Docs & release readiness

2–3 weeks, mostly parallel

Land the single-source-of-truth model the repo already half-built.

  • Final doc set: README.md, docs/LANGUAGE.md, docs/RUST_INTEROP.md, docs/STDLIB.md, docs/ROADMAP.md, generated status committed and CI-refreshed. Everything else lives under docs/archive/ or is deleted.
  • Move docs/gui/ (Coral content) into the Coral repo.
  • Rewrite the root README against measured numbers from this report, not the current aspirational "~75–80% parity" figure.
  • Add a LICENSE (none currently exists) and a CHANGELOG once the version starts moving past 0.1.0.

Every status above was verified by reading source (crates/*/src, stdlib/, tests/) and by actually running cargo build, cargo test --lib, and the .clr suite directly — not by trusting the repo's existing documentation, several files of which assert numbers this audit could not reproduce.
